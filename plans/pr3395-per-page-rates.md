# PR #3395 review follow-up: replace generic `perUnit` with concrete page pricing

## Context

PR #3395 (`feat/per-unit-cost-rates`, commits `a68df5b6` + `53cab026`) added per-page (OCR) pricing
through a **generic** billing-unit abstraction:

- `rates.perUnit = { unit: "page", price: "0.005" }` (`UnitRate` + `BillingUnit` enum)
- `Usage.units: Option<UnitUsage { unit, count }>`, `Breakdown.units`
- CEL `llm.cost.units`, `llm.costRates.perUnit`; log keys `agw.ai.usage.cost.units`
- `detect.rs` `lookups::PAGES` with two paths

@howardjohn's review ("overall lgtm, just a few small comments") rejects the generic unit:

1. `unit` is unfalsifiable for anything but pages (image = ? 320x320, video dimensions, mixed
   pages + tokens). Ask: make it concretely `pages` / `ocr_pages`, drop the abstraction.
2. `detect.rs:506` — `usage_info.pages_processed`: "where is this one? I only see
   usage.pages_processed".
3. `catalog/mod.rs:430` — `perUnit` → `perPage`.

Outcome wanted: same billing capability, zero generic-unit vocabulary in config, schema, CEL, or
Rust types.

## Findings so far

**Provider ground truth (Mistral OpenAPI, `https://docs.mistral.ai/openapi.yaml`):**
`OCRResponse` requires `usage_info: OCRUsageInfo`, and `OCRUsageInfo.pages_processed: integer`
("Number of pages processed"). The response example is `usage_info: { pages_processed: 29,
doc_size_bytes: null }`. There is **no** `usage.pages_processed` anywhere in the spec — so the
PR's first path is the correct one and the second (`usage.pages_processed`) is the unsourced one.
Howard's comment is inverted; this needs a PR reply with the spec citation, not a code change to
"fix" `usage_info`.

**Pricing math:** token lines are `count * rate / 1_000_000` (`model.rs:288-305`); the page line
must not divide. `line(tokens, rate)` (`model.rs:334`) already computes `count * rate` — so
`pages: line(usage.pages, self.per_page.as_ref())` reuses it and `unit_line()` +
`BillingUnit`-matching can be deleted outright.

**Blast radius of the rename (all current `units`/`per_unit` sites):**
- `crates/agentgateway/src/llm/catalog/model.rs`: `Rates.per_unit`, `Rates::overlay`, `BillingUnit`,
  `UnitRate`, `Usage.units`, `UnitUsage`, `Breakdown.units`, `Breakdown::total`,
  `Rates::breakdown`, `unit_line`, 5 new tests + 2 existing struct-literal tests (lines 542, 554).
- `crates/agentgateway/src/llm/catalog/mod.rs`: `CostRates.per_unit` (`#[dynamic(rename)]`),
  `From<&Rates>`, `Breakdown::components()` (array arity 9), `CostBreakdown.units`,
  `From<&Breakdown>`, `From<CostBreakdown>`, `VecMap::with_capacity(9)`, `usage_for`, 1 new test.
- `crates/agentgateway/src/cel/types_test.rs:302`.
- `crates/agentgateway/src/telemetry/log.rs:1550` (otel kv) and `:2081` (db kv).
- `crates/llm/src/lib.rs:387` `LLMResponse.pages` (name already concrete — keep).
- `crates/llm/src/types/detect.rs`: `lookups::PAGES`, buffered `to_llm_response`, streamed
  `amend_from_stream_response`.
- `schema/config.json`, `schema/config.md`, `schema/cel.json`, `schema/cel.md` are
  `linguist-generated`; regenerated by `cargo xtask schema` (`crates/xtask/src/schema.rs`).

## Approach

Collapse the abstraction to one concrete, per-page rate; keep the plumbing the PR already proved.

| Now | After |
| --- | --- |
| `rates.perUnit: UnitRate { unit, price }` | `rates.perPage: Money` |
| `BillingUnit`, `UnitRate`, `UnitUsage` | deleted |
| `Usage.units: Option<UnitUsage>` | `Usage.pages: u64` |
| `Breakdown.units` | `Breakdown.pages` |
| `unit_line()` | deleted; reuse `line()` without `/ unit` |
| CEL `llm.cost.units`, `llm.costRates.perUnit` | `llm.cost.pages`, `llm.costRates.perPage` |
| log `agw.ai.usage.cost.units` | `agw.ai.usage.cost.pages` |
| `lookups::PAGES` (2 paths, buffered + streamed) | 1 path `usage_info.pages_processed`, buffered only |

`rates.perPage` is documented explicitly as *USD per single page, unlike the token rates which are
per 1M* — the one wart of the flat shape, fixed by the doc comment that generated docs inherit.
`Usage.pages` as a plain `u64` (not `Option`) matches every sibling usage field and removes the
unit-equality guard: no rate ⇒ `Decimal::ZERO`, no pages ⇒ `0 * rate = 0`.

Tier overlay keeps working via the existing `pick()` closure (`per_page` is just another
`Option<Money>`), which also deletes the bespoke `or_else` line.

- [ ] `model.rs`: `Rates.per_unit: Option<UnitRate>` → `per_page: Option<Money>` with doc comment

- [ ] `model.rs`: delete `BillingUnit`, `UnitRate`, `UnitUsage`, `unit_line`; restore

- [ ] `model.rs`: `Usage.units` → `pages: u64`; `Breakdown.units` → `pages`; `total()` addend;

- [ ] `mod.rs`: `CostRates.per_unit` → `per_page` (`#[dynamic(rename = "perPage")]`, plain

- [ ] `cel/types_test.rs`: `units: dec("0")` → `pages: dec("0")`.

      delete the `_pages` `set_if` block in `amend_from_stream_response` (no provider streams a page

      `page_and_token_pricing_do_not_leak_into_each_other`, `tier_can_override_the_page_rate`,

- [ ] `cargo xtask schema` to regenerate the four schema files.
- [ ] `controller/pkg/cli/catalog/model_catalog.go`: add a `PerPage Money` field to `Rates` with tag

## Decisions (settled with the user)

- Flat `rates.perPage: Money`, not a nested object — matches sibling rates, kills `UnitRate`.
- `pages` / `perPage` naming everywhere (not `ocrPages`).
- `detect.rs` keeps only `usage_info.pages_processed`; the review thread gets the OpenAPI citation
  rather than a code change.
- Page lookup is buffered-only; the streaming `set_if` block is deleted.

## Non-goals

- No UI work: `ui/src/pages/Logs.tsx` renders a fixed cost-row list (`inputAudioCost`,
  `outputAudioCost`, …) and will simply not show a page row. The PR never added it; total cost is
  still correct because it comes from `agw.ai.usage.cost.total`.
- No page *count* telemetry (`gen_ai.usage.*`); only the page cost line, as in the PR.
- No entry added to `catalog/model-catalog.json` / overrides for `mistral-ocr-*` pricing.
